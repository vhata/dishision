## Summary

The core reasoning is clean on its boundary (no Worker, DOM, provider, clock or randomness imports) and the baseline is green, but the problems concentrate where text meets vocabulary. Exclusions, "Other" text, lexicon tagging and explanation phrases each match words in ways that let the wrong dish through or say something the data does not support. The most serious is that "no shrimp" or "no seafood" typed in "Other" does not exclude shrimp dishes. The Worker trusts the client on conversation order and stores raw GPS coordinates, which breaks the coarse-location invariant. The client has no guard against stale responses, so starting over during an in-flight answer brings the old session back. On the tooling side, `review-due.sh` exits 1 when there is no source churn since the latest review, which this review itself triggers: once it lands, the daily main-validation run goes red until the fix lands. Several documented gates and invariants (empty test project, `src/core` imports, PR body edits) have no enforcement behind them.

## Invariants

Carried from [ARCHITECTURE.md](../ARCHITECTURE.md#invariants) unchanged: core purity, knowledge base content in `kb/*.json`, deterministic ranking, grounded explanations, coarse location only, Zod before every D1 write, free-plan limits, copy tone. At the reviewed commit, the coarse-location invariant is broken (`session-coords-stored-at-full-precision`); the grounded-explanation invariant is broken (`explain-ungrounded-phrases`, `runner-up-comparative-ungrounded`); and the knowledge-base invariant is partly broken (`other-text-vocab-hardcoded`). The core-purity invariant holds by inspection but nothing enforces it (`core-import-invariant-unenforced`).

Added by this review, each because the same class of problem appears at least twice. They are proposed for `ARCHITECTURE.md`; adding them there is the user's call.

- **Ranking ties break on stable ids, not input order.** `rankCandidates`, `rankArchetypes` and the runner-up sentence sort by score and fall back to input order (stable sort). That is deterministic only while the candidate source returns rows in a fixed order, so a real provider could flip the primary or runner-up between requests.
- **Exclusions and matches use the vocabulary items are tagged with, matched as whole words or phrases.** Seafood sub-type exclusions that no item carries (`other-text-seafood-exclusions-miss`), substring exclusions (`cuisine-exclusion-tag-only` in TODO.md), single-word lexicon patterns (`lexicon-word-false-positives`, `lexicon-portion-side-marker`) and "Other" keyword false positives (`other-text-keyword-false-positives` in TODO.md) are four instances.
- **The server is authoritative for conversation order and session state.** Out-of-order answers (`answer-not-checked-against-current-question`), last-write-wins session updates (`session-mutations-race`) and client-side stale responses (`client-in-flight-requests-unguarded`) all assume the client sends one well-ordered request at a time.
