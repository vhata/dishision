# Decisions

Non-obvious choices and their trade-offs, dated, newest section first. Read the relevant entry before changing a mechanism that looks odd. Choices made autonomously under a delegation are recorded here for the user to review; an entry is a record, not a claim that the capability is complete.

Design-level decisions (free-tier constraints, minimal LLM use, no one-way doors, Google Places terms, D1-only storage) are in the design spec and are not restated here. Task-level rulings made while implementing phase 1 are in [`superpowers/plans/2026-10-08-dishision-phase-1-execution-log.md`](superpowers/plans/2026-10-08-dishision-phase-1-execution-log.md).

## 2026-10-13

| Decision | Reason and trade-off |
| --- | --- |
| A strong diet marker ("vegetarian", "vegan", "plant-based") overrides the meat a dish name implies only when the evidence is unambiguous: the marker is in the name; it is not negated, hedged or joined by a hyphen or dash to the word before it ("non-vegetarian", "not so vegan", "anti veggie", "ex-vegan", "half-vegan", "vegan-friendly", "vegan option"; Unicode dashes count as hyphens); it immediately precedes the meat phrase, separated by one plain space; and every meat word in the name and the description belongs to that one phrase. A weak marker ("veggie", "veg", "veggies") follows the same rules but overrides only meat that dish entries imply ("veggie burger", "veggie cheesesteak"), never a meat word. Otherwise meat wins and the vegetarian tag is dropped, as before. | A vegetarian pick that serves meat is worse than one that misses a vegetarian dish, so every doubtful case keeps the meat. "Veggie Burger", "Vegan Fish Tacos" and "Plant-Based Smash Burger" become vegetarian; "Beef and Veggie Stir Fry", "Veggie Burger w ham", "Vegan Cheese Chicken Pizza" and a veggie burger whose description offers bacon do not. An earlier version let known score-only words sit between the marker and the meat, but that list held nouns a marker modifies on its own ("cheese", "mayo", "soup", "curry"), so any word between now keeps the meat. Menus use "veggie" for "with vegetables" ("Veggie Chicken Pizza", "Veggie Beef Soup"), so it cannot cancel a meat word. The cost is missed vegetarian dishes: "Vegan Fried Chicken" and "Veggie Double Cheeseburger", "Veggie Sausage Pizza", "Veggie Chorizo" and "Veggie Fish Tacos", trailing or parenthesised markers ("Fish Tacos (vegan)"), quoted names ("Vegan \"Chicken\" Wings"), and any dish whose description mentions a meat word even to rule it out. A sweep of marker, modifier, meat-word, suffix and description combinations against main found the vegetarian-only results only where a claiming marker sat directly before the dish's only meat phrase. So the rule errs toward vegetarian in two places: a meat word the lexicon does not know, added to a marked dish ("Veggie Burger with" an unlisted cut or sausage), is invisible, so the vocabulary has to keep growing with real menus; and a weak marker before a dish name ("veggie poke", "veggie pozole") is read as meat-free even on a menu that means extra vegetables. A negated or hedged marker also no longer tags vegetarian on its own. |
| The marker words live in `kb/lexicon.json`, in two entries: the tagger finds the strong one as the vegetarian entry whose pattern matches the word "vegetarian" and the weak one as the vegetarian entry whose pattern matches "veggie". Vegetarian ingredient words (tofu, vegetables, chickpeas) are a separate entry and never act as markers. | Keeps lexicon vocabulary out of code without a schema change (the schema drops unknown keys, so an entry cannot carry a role field): an overlay can add a marker word by extending either entry. The convention is implicit, so a vegetarian entry that happens to match one of the two probe words becomes a marker entry. The negation and hedge words stay in `lexicon.ts` because they are grammar for the rule, not tagging vocabulary. |
| Meat words beyond the dish and protein patterns are lexicon entries with no scores. Words with a true mapping tag the existing protein key: cured pork and sausages (bacon, pepperoni, salami, bratwurst, spam) as pork; anchovy, roe, eel, ahi and lox as seafood; veal, wagyu, bison, galbi and jerky as beef, with "dak galbi" as chicken and "dwaeji galbi" as pork; hot dogs and meatballs as beef and pork; birria as beef and goat. Other meats tag detection-only proteins that no preference asks for: `lamb` (lamb, mutton), `goat`, `game` (venison, rabbit), `poultry` (turkey, duck, goose, quail) and `offal` (liver, tripe). Any protein tag other than vegetarian counts as meat. | Without them those words were invisible, so "Veggie Burger with Bacon" stayed vegetarian and "Vegetable Duck Curry" tagged vegetarian. The schema already allows any protein string, a protein preference scores an unknown tag 0, and the vegetarian rule needs only "not vegetarian", so detection needs no new protein key; adding lamb or poultry to the preference model is a separate change. Mapping lamb to beef or duck to chicken would have made "no beef" in Other text drop lamb dishes and "no chicken" drop duck. Guards in the patterns, all lookarounds: a goat word followed by a space or dash and a dairy word ("goat cheese", "goat-cheese", "goat gouda") is not meat, nor is "duck sauce", "duck egg" (but "duck egg rolls" is) or "eel sauce" with a space or dash, and marrow is meat only as "bone marrow". The mixed-protein words take no default when another protein or a substitute names them ("chicken meatballs", "turkey meatballs", "chicken birria", "birria de pollo"), so they never add beef to a chicken or pork dish; markers are left to the marker rule, so "Non-Vegan Hot Dog" stays meat. A true substitute just before a new meat word hides it ("mock duck", "seitan bacon", "tempeh bacon"), and so do a few unambiguous pairs ("coconut bacon", "mushroom jerky", "carrot lox", and "tofu" only before poultry: "tofu duck"); a vegetable word in general does not, because "coconut duck curry" and "mushroom bacon pasta" are meat, and tofu is often the base meat sits on ("tofu with roe", "tofu bacon fried rice"). The bare word "meat" is not a meat word because of "crab meat", "coconut meat" and "plant-based meat". The extra hits raise a matching item's lexicon confidence slightly. |

## 2026-10-12

| Decision | Reason and trade-off |
| --- | --- |
| Biome (pinned exactly, 2.5.15 at adoption) is the formatter and linter, gated by `scripts/fmt-check.sh` and `scripts/lint.sh`. | The owner asked for the current consensus choice rather than the most common one. Biome is one stable tool for formatting, import sorting and linting, with type-aware rules and close Prettier compatibility, so there is one config and no ESLint plugin set to maintain. Oxlint with oxfmt is faster, but oxfmt was still 0.x; reconsider when it reaches 1.0. An exact pin because a Biome release can change formatting output. |
| Line width 140, single quotes, semicolons, trailing commas. | Matches how phase 1 was written. At 140 the reformat touched 32 files; 100 would have touched 52 and roughly tripled the churn. |
| The formatter skips `kb/**/*.json` and `fixtures/**`; the linter still covers them. | Those files are tables with one record per line, which is how they are read and reviewed. Formatting them would have expanded each record into a dozen or more lines for no gain in correctness. |
| `style/noNonNullAssertion` is off. | `noUncheckedIndexedAccess` makes `!` the explicit, reviewable marker of an index the code knows is present (76 sites, most in tests). The rule would push those sites toward `as` casts or unreachable guards, which hide the same assumption less visibly. |
| Pre-commit runs Biome on the staged copies of code files, extracted to a temporary directory with the staged `biome.json` and `package.json` (Biome enables its React and test rules from `package.json`). | The 2026-10-09 entry put code gates on push but said a formatter gate belongs on commit. Biome over a typical change takes well under a second. Checking the index rather than the working tree means a partly staged file is judged on what will be committed. |

## 2026-10-11

| Decision | Reason and trade-off |
| --- | --- |
| The generic workflow (contract, queue and review guides, validators) is vendored under `docket/` by the docket skill's `install.sh` and never edited here; `AGENTS.md` keeps only the project's settings in its marked Docket section, and the review focus areas, baseline commands and drift checks live in `docs/QUALITY.md`. | One command installs or resyncs the whole directory and `--check` reports any drift, so a fix to a validator reaches this project without a hand merge. The cost is that a project-specific rule can no longer be written into a guide; it goes in the Docket section or the quality doc, which the guides point to. |

## 2026-10-09

| Decision | Reason and trade-off |
| --- | --- |
| The agent workflow (contract, queues, gates, review ledger, CI) was installed on a branch stacked on `phase-1-conversation-and-ranking`, not on `main`. | `main` held only the spec and the plan, so gate scripts based on it would have had nothing to check and CI would have been red until the code landed. Stacking meant the install PR could not land before the phase-1 PR; the alternative, installing docs first and gates later, would have left the first code PR ungated. Phase 1 landed first (#1), and the install branch was rebased onto `main` and retargeted the same day. |
| Git hooks are a tracked `.githooks/` directory wired with `core.hooksPath`, installed by `scripts/setup.sh`. | No hook-manager dependency (lefthook, husky, simple-git-hooks) to pin or download; one `git config` covers every worktree. Cost: hooks are plain bash, so per-file staging tricks are hand-written if ever needed. |
| Pre-commit runs only the queue and link validators, and only when queue or Markdown files are staged. Typecheck and tests run on pre-push. | Typecheck plus the three test projects take about five seconds warm, over the two-to-three-second pre-commit budget; a push-time run still precedes every CI run. Change if a formatter gate arrives, which belongs on commit. |
| No formatter or linter gate yet; `scripts/check.sh` runs typecheck and tests. | Nothing was chosen in phase 1 and adopting one means reformatting the whole tree, which is its own PR. Filed as `adopt-formatter-and-linter` in `TODO.md` for the user to decide on. |
| `scripts/test.sh` passes `--passWithNoTests=false` explicitly. | Vitest 4 already fails on empty collection by default, but the flag makes the policy visible and survives a default change. |
| `CLAUDE.md` is the single line `@AGENTS.md`; the invariants it used to hold moved to `ARCHITECTURE.md`. | One authoritative home per rule; Claude Code imports the contract and other harnesses read `AGENTS.md` directly. |
| Node is pinned by `.nvmrc` (26) and pnpm by `packageManager` in `package.json`; CI reads both from the files, never from a version typed into a workflow. | Toolchain bumps become reviewable diffs in the repository rather than silent runner changes. |
